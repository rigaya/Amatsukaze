# EDCB連携時の実行コンテキストとトラブルシューティング

EDCBの録画後実行バッチからAmatsukazeにタスクを投入する構成では、
「どのアカウント・セッションでバッチが実行されるか（実行コンテキスト）」によって、
発生する問題が大きく変わります。このドキュメントは、その組み合わせを整理したものです。

## 前提知識

- EDCBの録画後実行バッチは、**EpgTimerSrvと同じ実行コンテキスト**で実行されます。
- AmatsukazeAddTaskがサーバーに接続できない場合、ローカルなら**サーバーを成り行き起動**します。
  このとき起動されたサーバーは、**バッチの実行コンテキストをそのまま引き継ぎます**。
- 問題の多くは「サーバーが意図しないコンテキストで起動されてしまった」ことが原因です。

## 起動時の診断ログ

AmatsukazeServer / AmatsukazeAddTask は起動時に実行コンテキストをログに出力します。

```
[起動診断] アカウント=..., セッションID=..., 対話型=..., アカウント種別=..., 管理者権限=..., ANSIコードページ=...
```

トラブル時はまずこの行を確認してください。

- **アカウント種別** が LocalSystem / LocalService / NetworkService → サービスコンテキストで動作しています
- **セッションID=0** → サービス用セッションです（GUIは表示されません）
- **ANSIコードページ=65001** → Windowsの「Unicode UTF-8を使用する」設定が有効です（文字化けの一因）

## 実行コンテキスト × 投入経路 マトリクス

| バッチの実行コンテキスト | サーバー事前起動あり | サーバー成り行き起動 |
|---|---|---|
| ユーザー（EpgTimerSrvをスタートアップ等で通常起動） | ◎ 推奨構成。問題なし | ○ 動作するが下記「共通の注意」参照 |
| LocalSystem（EpgTimer Serviceをサービス登録・既定） | ○ タスク投入のみなら可 | × サーバーがLocalSystem/セッション0で起動。ネットワークドライブ（ドライブレター）不可視・AviSynthプラグインエラー・GUI不可視・ユーザーから「起動していない」ように見える |
| LocalService（サービス登録時にオプション選択） | ○ タスク投入のみなら可 | × 上記に加えて、録画フォルダへのアクセスにACL付与が必要・ネットワーク共有へは実質アクセス不可 |

### 共通の注意（コンテキストに依らない既知の問題）

1. **ファイアウォール**: EDCB経由で初めてAmatsukazeServerが起動されると、
   ファイアウォールのダイアログが表示できずブロックされ、「録画後に何も起きない」ように見えます。
   → 事前に一度手動起動して許可してください。
2. **カレントディレクトリ**: AmatsukazeAddTaskを生成バッチ以外から直接実行する場合でも
   動作するようになっていますが、exeを単体で別の場所にコピーした場合は
   ルートフォルダを解決できず、成り行き起動に失敗します。
3. **文字コード**: Windowsの「Unicode UTF-8を使用する」(ANSIコードページ65001)が有効な環境では
   CLI出力等が文字化けすることがあります（既知の問題）。
4. **UACによるドライブレター分離**: 管理者に昇格したプロセスからは、非昇格セッションで割り当てた
   ネットワークドライブが見えないことがあります（EnableLinkedConnections未設定時）。
   「管理者として実行」で回避しようとすると、かえってドライブが見えなくなる場合があります。

## 推奨構成

1. **AmatsukazeServerをユーザーセッションで事前起動しておく**（最重要）。
   自動化したい場合はタスクスケジューラで「ログオン時」トリガー・ユーザーアカウント指定で登録してください。
2. EDCBをサービス化している場合、録画後バッチからの成り行き起動には頼らない。
3. ネットワーク上のファイルを扱う場合、ドライブレターではなくUNCパス（\\server\share\...）を使う。

## 診断ログで問題を切り分ける手順

1. 「録画後に何も起きない」→ ファイアウォール確認 → バッチのログ（EDCB側）を確認
2. 「サーバーは起動しているのにエラーになる」→ サーバーログの `[起動診断]` 行を確認
   - アカウント種別がサービス系 → ユーザーセッションで事前起動する構成へ変更
   - ANSIコードページ=65001 → 「Unicode UTF-8を使用する」を無効化
3. 「起動しないように見える」→ サービスコンテキストで既に起動している可能性。
   クライアントから接続を試す（README「EDCBから自動エンコード」参照）
